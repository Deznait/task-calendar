# Task Calendar - Instrucciones de Copilot

Instrucciones personalizadas para mejorar la generación de código y asistencia en el proyecto Task Calendar.

## Convenciones de código

### TypeScript

- Usar tipos **explícitos** siempre (nunca `any`)
- Preferir interfaces sobre types para definiciones de objetos
- Usar `type` solo para uniones y tipos primitivos complejos
- Los nombres de archivos con tipos deben tener extensión `.ts` (ej: `models.ts`, `types.ts`)

### Vue 3 + Quasar

- Usar **Composition API** con `<script setup>`
- Mantener la reactividad con `ref` y `computed`
- Los componentes siempre tipados: `defineProps<Props>()`, `defineEmits<Emits>()`
- Usar `quasar` para imports de componentes UI

### Archivos

- **Composables**: `use*` (ej: `useCalendar.ts`, `useAuth.ts`)
- **Stores**: `*.store.ts` (ej: `tasks.store.ts`, `auth.store.ts`)
- **Componentes**: `*.vue` en PascalCase
- **Páginas**: `*.vue` en src/pages/ (enrutables)
- **Layouts**: `*.vue` en src/layouts/

### Tipos con Interfaces

- Definir en `src/types/index.ts`
- Usar **interfaz por cada concepto** (Task, Category, etc.)
- Incluir campos de auditoría: `created_at`, `updated_at`
- Usar UUIDs para IDs: `id: string`
- Campos opcionales con `?`: `description?: string | null`

## Funcionalidades clave

### Tareas recurrentes (RRule)

- Las tareas pueden tener `rrule` (formato RFC 5545)
- Campo `dtstart` = fecha/hora de inicio
- Campo `exdates` = array de excepciones
- El composable `useCalendar` calcula ocurrencias dinámicamente
- **NO** generar todas las ocurrencias, calcularlas bajo demanda

### Completamientos

- Registrar en `task_completions` (tarea + fecha)
- Permitir notas y estado de ánimo (mood 1-10)
- Usar fecha, no timestamp (ej: `2024-01-15`)

### Overrides

- Permitir modificar ocurrencias individuales
- Campos: `title`, `description`, `new_date`, `deleted`
- Si `deleted: true`, la ocurrencia no aparece

### Internacionalización

- Siempre usar `$t('key.nested.path')` en templates
- Definir traducciones en `src/i18n/locales/{ca,en,es}.ts`
- Mantener estructura consistente entre idiomas

## Mejores prácticas

### Manejo de errores

- Usar `try/catch` en acciones async
- Console.error para debugging
- Mostrar mensajes al usuario vía Quasar Notify/Dialog

### Supabase

- Reutilizar la instancia: `import { supabase } from 'src/boot/supabase'`
- Usar `.select()` explícitamente
- Manejar errores con `.error` en respuestas
- Filtros: `.eq()`, `.gte()`, `.lte()`, `.in()`, etc.

### Performance

- Usar `computed` para cálculos derivados
- Evitar watchers a menos que sea necesario
- Lazy-load componentes si es posible
- Paginar resultados grandes

### Tests

- Componentes: `*.spec.ts` junto a componente
- Stores: `*.spec.ts` en carpeta tests/
- Usar testing library para componentes Vue

## Notas importantes

- ⚠️ **Nunca hardcodear** URLs, IDs o textos. Usar variables de entorno o config.
- ⚠️ **RLS en Supabase** debe estar activo. Las queries respetan `user_id` automáticamente.
- ⚠️ **Dates**: Usar `Date` en frontend, ISO strings en BD/API
- ⚠️ **Soft deletes**: Tareas con `is_active: false` no se cargan
- ✅ Siempre documentar funciones complejas con comentarios
